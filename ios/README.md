# MIBR GC

Match-day brief for **MIBR GC** and **Team Liquid Brazil**, 2026 only. The app reads a bundled `brief.json`. It does not download VLR itself.

Open `MIBRGC.xcodeproj`, select the **MIBRGC** scheme, and run it on a simulator. The deployment target is iOS 15. The bundle id is `com.lorena.mibrgc`. Signing is turned off for the simulator build.

## Screens

The first screen is the roster choice. After that, four tabs:

- **Report** — series, maps, round differential, attack and defense, the economy states they lose most, the map chart, and the roster cards
- **Rival** — the series against the other roster (Liquid on a MIBR GC brief, MIBR on a Team Liquid Brazil brief)
- **Veto** — the map card for the circuit you selected
- **Cues** — three rehearsal lines

English and Portuguese, and the Brazil circuit versus the international sheet, sit in the header. The back arrow returns to the roster choice.

The Brazil sheet is Kickoff, Stage 1, Stage 2, and Finals. Championship and AMER Last Chance are the international check. VCL is left out of both.

## Refresh the numbers

From the repository root, after the tables exist:

```bash
python -m matchday.export_ios
```

That rewrites `ios/MIBRGC/brief.json`. Rebuild the app so the bundle picks up the new file.

Fetch a roster first if its tables are missing:

```bash
python -m mibrgc fetch
python -m mibrgc fetch --team team-liquid-brazil
```

MIBR GC tables stay in `data/processed`. Team Liquid Brazil tables stay in `data/team-liquid-brazil/processed`.

## Files

| File | Role |
| --- | --- |
| `MIBRGC/MIBRGCApp.swift` | Roster choice, header, and the tab bar |
| `MIBRGC/BriefViews.swift` | Report, rival, veto, and cues |
| `MIBRGC/Models.swift` | The `brief.json` model and the colors |
| `MIBRGC/brief.json` | Both rosters, generated by `python -m matchday.export_ios` |

## Launch arguments

Optional. They skip the saved language, circuit, and roster:

- `-lang en` or `-lang pt`
- `-scope brazil` or `-scope international`
- `-team mibr-gc` or `-team team-liquid-brazil`

Set them in the scheme under **Run → Arguments Passed On Launch**.
